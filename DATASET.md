# Dataset

## Status

**No dataset exists yet.** No documents have been collected and no synthetic projects have been
generated. This document defines the schema and the rules that the Phase 1 and Phase 2 work
will produce, so that the shape is agreed before data starts accumulating.

## Layout

```
data/
  raw/          immutable, content-addressed. Never modified, never deleted.
  processed/    parsed text, OCR output. Regenerable.
  normalized/   canonical entities. Regenerable.
  labeled/      ground truth and annotations.
  synthetic/    generated projects with their truth files.
```

Object keys (see [`storage/keys.py`](src/aedifex/infrastructure/storage/keys.py)):

```
raw/<source_id>/<aa>/<bb>/<sha256><ext>
<tier>/<stage>/<aa>/<bb>/<sha256>.<ext>
```

`aa`/`bb` are the first two digest byte-pairs, for even sharding. Keys contain **no
timestamp**: the same document re-downloaded next month must land on the same key, which is
what makes re-running a crawl idempotent. Time-based questions are answered by the metadata
database, which is where they belong.

Derived artifacts are keyed by the digest of the **raw document they came from**, so every
processed artifact traces back to the exact bytes that produced it.

## Provenance

Every extracted fact must carry its origin. Losing this breaks the product's core promise: a
finding that cannot be traced to a page and a location is not auditable.

```json
{
  "field": "material_grade",
  "value": "Fe500",
  "normalized_value": "FE500",
  "source_document": "MTC-101.pdf",
  "document_id": "…",
  "page": 2,
  "bbox": [102, 430, 344, 476],
  "extraction_method": "ocr",
  "extractor_version": "paddleocr-2.7",
  "confidence": 0.97
}
```

The chain `claim → document → page → location → method → confidence` is never broken.

## Synthetic dataset

### Target for the first release

| Artifact | Count |

### The rule that matters

**Generate internally consistent project histories, not random documents.**

A random invoice teaches nothing. The value is in a coherent history where a PO for 120 MT of
Fe500D at ₹62,000/MT is followed by a challan, a GRN for 118 MT, a certificate, and an invoice
— so that an injected inconsistency is *the only* thing wrong, and a rule that fires on it has
demonstrably found the right thing.

### Anomaly injection

Anomalies are injected deliberately, and every one is recorded in ground truth.

**Financial** — invoice exceeds PO value; unit rate mismatch; arithmetic error; duplicate
invoice; duplicate with a slightly altered number; inconsistent GST; invalid totals;
unsupported charges; invoice dated before its PO.

**Procurement** — wrong vendor; missing PO; unauthorised vendor; changed quantity; product
mismatch; missing change order; expired PO.

**Delivery** — delivered quantity below invoiced; delivery after invoice; duplicate challan;
mismatched vehicle or vendor; missing receiving acknowledgement.

**Material** — wrong grade; wrong specification; wrong manufacturer; certificate batch not
matching the shipment; expired certificate; missing test values; values outside tolerance.

**Contract** — payment condition unmet; missing inspection; missing approval; expired bank
guarantee; contract value exceeded; missing variation order.

### Ground truth

One machine-readable truth file per project:

```json
{
  "project_id": "project_0001",
  "generator_version": "0.1.0",
  "seed": 42,
  "documents": [],
  "relationships": [],
  "expected_findings": [
    {
      "finding_id": "F001",
      "type": "quantity_mismatch",
      "severity": "high",
      "source_document": "INV-001",
      "comparison_document": "GRN-001",
      "invoice_quantity": 125,
      "received_quantity": 118,
      "difference": 7
    }
  ]
}
```

Truth must include expected entities, expected extracted fields, document relationships, known
anomalies, expected rule outcomes, expected severities, and expected evidence references.

`seed` is mandatory: a dataset that cannot be regenerated byte-for-byte is not a dataset, it is
an artifact.

### Generation constraints

- Vendor and project names must be obviously fictional. A collision with a real company is a
  bug in the name pool.
- Synthetic documents flow through the same hashing, deduplication, and storage path as
  collected ones (`synthetic_projects` is a registered source). A separate path would let bugs
  hide.
- **No unintentional duplicates.** Two documents that were meant to differ but hash identically
  are a generator bug, and would corrupt any deduplication metric.

## Dataset validation

Automated, and required. Validation must assert:

- Unique document IDs; no unintended duplicate digests
- Valid foreign keys — every referenced PO, vendor, and document exists
- Expected relationships present and correctly directed
- Numeric values within plausible ranges; correct currency
- Date ordering coherent (PO before invoice, delivery before GRN)
- **Every anomaly label corresponds to an actual anomaly in the documents, and every injected
  anomaly is labelled.** A truth file that disagrees with its own documents is worse than no
  truth file, because it would silently corrupt every precision and recall number computed
  from it.

## Versioning

Datasets are versioned products: `construction-audit-dataset-v0.1`, `v0.2`, … with a changelog
per version recording what changed and why.

Reproducibility target:

```
dataset version + code commit + model version + prompt version + rules version
    = the same audit result
```

For an auditing system this is not a nicety. A finding that cannot be reproduced cannot be
defended.

DVC or lakeFS may be adopted later; object-storage versioning plus a manifest is sufficient at
this scale and is not worth the added tooling yet.

## Licensing and provenance obligations

Each source records its licence, permitted use, access level, and whether it contains personal
data. That metadata travels with the corpus and is exposed via `GET /v1/sources`. Documents
collected from a source may only be used within its recorded `allowed_use`, so any derived or
redistributed dataset must be filtered by source accordingly.

### Ownership

Downloading a public document does not make it ours. The tiers keep the distinction visible:

```
raw/          third-party content, owned by whoever published it
normalized/   ─┐
labeled/       ├─ the value we add: selection, organisation, annotation,
synthetic/    ─┘  relationships, labels, derived ontology, evaluation sets
```

What may be proprietary is that added value, subject to source rights and applicable law — never
the underlying third-party material itself.

**Training eligibility is a separate state from collection eligibility.** Raw collected documents
must never automatically become training data:

```
collected → licence validation → PII screening → redaction → quality review → approved corpus
```

Never commit customer documents, vendor proprietary specifications, paid databases, or licensed
standards without redistribution rights — not even as test fixtures. For standards such as BIS/IS
codes, store permitted metadata and references separately from copyrighted text; being able to view
a standard does not permit copying it into this repository or a training corpus.
