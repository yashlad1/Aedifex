# Diagrams

Dated and **never overwritten**: `YYYY-MM-DD-subject-vN.md`.

Keeping historical versions rather than editing one file in place preserves how the architecture
developed and when, which is exactly what a later assessment needs.

Each diagram should identify inputs, components, relationships, trust boundaries, processing
sequence, and outputs.

Existing diagrams elsewhere in the repository that may be worth snapshotting here when they
stabilise: the layer diagram in `ARCHITECTURE.md`, the frontier/content split in `DATA_MODEL.md`,
and the trust-boundary diagram in `docs/security/threat-model-http-fetch.md`.
