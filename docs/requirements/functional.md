rather than asserted.

## Acquisition

| ID | Requirement | Status | Evidence |
| --- | --- | --- | --- |
| FR-070 | The system shall download publicly available construction procurement documents. | **Mechanism implemented; blocked on source approval** | `test_download.py`, and `TestADocumentEndToEnd` takes a PDF from a URL through the guard, a redirect, a retried 503, a real socket, and onto disk with a matching digest. No source is enabled, so nothing has been downloaded from a real portal |
| FR-071 | The system shall rate-limit, retry with backoff, and bound concurrency per source. | Implemented | `test_fetch_ratelimit.py`, `test_fetch_controller.py`; see [fetch.md](fetch.md) FR-130–135, FR-140–148 |
| FR-072 | The system shall resume an interrupted crawl without duplicating work. | Implemented | `CrawlRunner` reopens the source's already-running job rather than starting a second one, so counters and limits survive. A URL already `DOWNLOADED` is skipped without touching the network; a lease is written before the request, so a crashed worker leaves evidence and its URLs are reclaimed rather than lost. What is still deliberately absent is re-fetching a *known* URL to check for change: a changed document has a different digest and is therefore a different document, which is a design question and not a flag |
| FR-073 | The system shall identify itself with a User-Agent carrying a contact address. | Implemented | `test_anonymous_user_agent_is_rejected` |
| FR-074 | The system shall derive every per-source fetch policy — permitted hosts, rate limits, accepted formats, and payload ceiling — from that source's registry entry, and shall refuse to build one for a source that is not enabled and approved. | Implemented | `AcquisitionPolicy.from_source`; `test_pipeline.py::TestPolicyComesFromTheRegistry`, `TestTheReviewGateIsEnforcedAtTheDoor`, and an invariant over the shipped YAML in `TestAgainstTheShippedRegistry`. The four `from_source` builders existed already and nothing assembled them, so each caller wired them by hand and could pair one source's host allowlist with another's rate limits. Making it the single door also makes it the place the review gate binds at the point of use: ADR 0006 stops an unreviewed source being *enabled*, and this stops a disabled one producing traffic. The refusal is deliberately not an `AcquisitionError`, because the acquirer catches those and would record "we may not collect from this portal" as one URL's failure and carry on to the next URL of the same source |
| FR-075 | The system shall maintain a persistent crawl queue that survives interruption, leasing each URL to one worker at a time and recovering URLs whose worker stopped without recording an outcome. | Implemented | `FrontierQueue`; `test_frontier.py`. `FOR UPDATE SKIP LOCKED` with a lease rather than a state change, so the acquirer keeps sole ownership of the document state machine. Delivery is at-least-once, effectively-once by content addressing ([ADR 0012](../adr/0012-postgresql-frontier-queue.md)) |
| FR-076 | The system shall treat two spellings of one URL as one frontier entry, and shall not collapse URLs that may denote different documents. | Implemented | `canonical.py`; `test_two_spellings_of_one_url_become_one_row`. Case, default port, and fragment are normalised by the same function the SSRF guard uses; query order, trailing slashes, and path case are deliberately *not*, because all three can change which document a portal serves |
| FR-077 | The system shall stop retrying a URL after a bounded number of attempts and record it for operator review. | Implemented | `dead_lettered_at`, set by `settle` and by `reclaim_expired`; `test_a_dead_worker_does_not_hold_its_url_forever` walks a poison URL to dead-letter. Closes rule 47's requirement for the crawl queue; FR-056's job-level dead-lettering is still planned |
| FR-078 | The system shall schedule discovery, enqueue what it finds, invoke the downloader, persist results, record failures, and resume an interrupted run. | Implemented | `CrawlRunner`. One transaction per URL, so a crash loses at most that URL's work; limits are evaluated against the job's *persisted* counters, so a run capped at 100 documents and interrupted at 60 fetches 40 more when resumed. Verified by execution: a full crawl against a local portal, robots to MinIO to provenance |
| FR-079 | The system shall expose a corpus catalog recording source, original URL, retrieval time, SHA-256, object key, MIME type, resolved format, retrieval status, and provenance. | Implemented | `catalog.py` and `GET /v1/documents`, `/v1/corpus`. A read model over the three existing tables, not a fourth copy: a catalog *table* would be a fourth record of facts already held, and a fourth record can disagree with the other three |
| FR-080a | The system shall report per-run operational metrics: URLs discovered and skipped, documents stored, duplicated, failed and quarantined, bytes downloaded, success and duplicate rates, queue depth, and crawl duration. | Implemented | `crawl_jobs` counters, `GET /v1/crawl-runs`, `make status`, and one structured `crawl.finished` event. Counts and rates only — no URLs or document ids — so it stays graphable without a cardinality explosion (rule 62). Queue depth is a query, not a counter, because a counter drifts |
| FR-081a | The system shall support a discovery-only rehearsal of a source that downloads nothing. | Implemented | `CrawlLimits(dry_run=True)`, `make crawl s=<id> dry=1`. A portal nobody has crawled deserves a rehearsal, and it costs the site only its listing pages. Verified by execution: the portal's access log showed robots.txt and two listing pages and no document requests, and the frontier was left exactly as a real run would find it |
| FR-081b | The system shall take its per-request timeout budget from the source's own registry entry. | Implemented | `SourceTimeouts`, translated to the fetch layer's `TimeoutPolicy` by `AcquisitionPolicy.from_source`. Found by execution, not design: the first live crawl recorded a 1.11 MB PDF as failed because NHAI answered in 31 seconds and the global default read timeout was 30. Slowness is a property of a portal, so it belongs beside that portal's rate limits. Bounded above (read ≤ 300s, total ≤ 1800s) because an unbounded timeout is how a crawl becomes a hung process, and the budget is validated at load time so a contradictory entry fails when the file is read rather than at the first fetch |

## Audit engine

| ID | Requirement | Status |
| --- | --- | --- |
| FR-080 | The system shall build an evidence graph relating documents, vendors, and materials. | Planned |
| FR-081 | The system shall evaluate versioned deterministic rules over the evidence graph. | Planned |
| FR-088 | The system shall extract text from an acquired PDF under explicit page and character bounds. | Implemented | `extraction/pdftext.py`. A PDF is untrusted remote content, and passing the acquisition layer's size and type checks says nothing about what happens when something parses it. Every pypdf failure becomes `ExtractionError`; one unreadable page is recorded empty rather than losing the document. An image-only PDF reports `has_text_layer=False` — a limitation needing OCR, not a failure |
| FR-089 | The system shall extract named facts from a document with the page and span that support each one. | Implemented | `extraction/tender_notice.py`, `extracted_facts`. NIT number, estimated cost, bid security, and the prescribed bid-security share. Amounts parse Indian digit grouping and adjacent unit words (`16.93 Lacs` → 1,693,000) via `extraction/quantities.py`; a unit word is honoured only next to the number, never from a column header — a real table headed "Estimated Cost (Rs. In Crore)" holds a value already in rupees, and trusting the header would multiply it by ten million |
| FR-096 | The system shall source a rule's threshold from evidence, or decline to judge. | Implemented | The prescribed bid-security share is an *extracted fact* — one bid document states 1% in ITB clause 13.2, page 13 — supplied to the rule as an input. Found by reading the corpus rather than assuming: the first notice read implied 2%, and hardcoding it would have failed a legitimate 1% tender. Where no rate is sourced the ratio is measured and reported `INCONCLUSIVE` |
| FR-097 | The system shall make re-analysis of a document idempotent. | Implemented | Unique constraints on (document, fact type, extractor version) and (document, rule, rule version); `extraction/store.py` reads before writing and rebuilds evidence links. Verified by execution: two consecutive `analyse --all` runs left 6 facts, 4 findings, 4 evidence links and zero duplicates. A changed extractor gets a new version and new rows, so a finding stays explicable against the values that produced it |
| FR-098 | The system shall group documents into projects using an identifier the documents themselves state. | Implemented | `extraction/projects.py`, `projects` / `project_documents`. Membership is exact string equality on an extracted identifier fact, so every grouping can be defended by pointing at a page span in each document. Never inferred by a model, never guessed from a filename or page count. `established_by` records what justified it |
| FR-099 | The system shall store relationships between documents as first-class, provenanced rows. | Implemented | `document_relationships`. Symmetric relationships are stored once in a canonical direction so two rows for one fact cannot disagree. Only `same_tender` is currently derivable; the rest of the vocabulary in `domain/evidence.py` is declared because a relationship that has no name cannot be stored |
| FR-100a | The system shall represent facts by kind independently of the field that produced them. | Implemented | `FactKind` in `domain/evidence.py`, `extracted_facts.kind`. The shared fact model: `estimated_cost` and `invoice_total` are different facts and both are money, so a cross-document rule selects on kind and one comparison serves every money fact rather than being rewritten per document type |
| FR-101 | The system shall evaluate deterministic rules over facts from more than one document. | Implemented | `verification/cross_document.py`, `analyse --project` / `--all-projects`, `GET /v1/projects/{id}/findings`. Findings are scoped to the project because "these two documents disagree" is not a fact about either one. Verified by execution on two real NHAI documents of one tender, and by test for the disagreement path the corpus cannot produce |
| FR-102 | The system shall report a disagreement between documents without resolving it. | Implemented | The rule states both values, cites both spans, and stops; it has no basis for deciding which document is right, and picking one would be the rule inventing a fact. A project with nothing stated twice returns INCONCLUSIVE rather than agreement — nothing compared is not a pass |
| FR-103 | The system shall persist deterministic calculations as first-class derived facts. | Implemented | `derived_facts` / `derived_fact_inputs`, `calculation/engine.py`. Each records its inputs, the calculation, its version, the producing module, and the arithmetic as text — so the number can be redone by hand from the stored row alone. A value computed inside a rule and discarded leaves a finding asserting a figure nobody can re-derive |
| FR-104 | The system shall separate calculation from judgement. | Implemented | The calculation layer produces values and cannot produce verdicts: `PASS`, `FAIL` and `INCONCLUSIVE` do not appear in it and its return type has nowhere to put them. That separation is what makes a derived fact reusable — `bid_security_share` is true whether the prescribed rate is 1%, 2%, or unknown |
| FR-105 | The system shall allow more than one rule to consume the same derived fact. | Implemented | `bid_security_share` is consumed by the single-document rule (against a prescribed rate) and by the cross-document consistency rule (against the other documents of its project). Neither divides; the division happens once. Verified by execution: both findings cite the same derived rows |
| FR-106 | The system shall order a project's documents chronologically from extracted dates. | Implemented | `document_date` fact with a real `date_value` column, shown as `CHRONOLOGY` in `analyse --project`. A `DATE` column rather than text because 07.09.2026 sorts before 07.08.2026 as a string, and ordering is the only reason to extract the date |
| FR-107 | The system shall publish the vocabulary it can reason about. | Implemented | `knowledge/registry.py`, `GET /v1/knowledge`. Metadata only — no DSL, no ontology engine, no dispatch. A test asserts every registered type is one the code can actually produce, so it cannot drift into documenting features that do not exist |
| FR-108 | The system shall distinguish extracted evidence from computed evidence when citing it. | Implemented | `FactOrigin`, `finding_evidence` citing exactly one of a fact or a derived fact, enforced by check constraint. The CLI labels one `evidence` and the other `derived`; the API sets `origin`. Both are citable, but nobody wrote the computed one down and presenting them identically would blur that |
| FR-109 | The system shall ingest a local file as evidence, recording an upload rather than a retrieval. | Implemented | `extraction/ingest.py`, `document_uploads`. A separate provenance table because an upload has a path and an uploader while a retrieval has a URL and an HTTP status; reusing the retrieval row would have meant inventing an HTTP 200 for a request nobody made. Same content addressing, so ingesting bytes already crawled resolves to the same document. Restricted to approved `manual_upload` sources |
| FR-110 | The system shall extract facts from construction spreadsheets with a cell reference for each. | Implemented | `extraction/spreadsheet.py`. Header matching by alias, never by position — a positional reader swaps quantity for rate the first time someone inserts a column. `Rate` resolves to the contracted or the claimed rate according to document type, since a BOQ and a running bill label it identically and mean different things. Evidence is `BOQ!D7`, the spreadsheet equivalent of a character span |
| FR-111 | The system shall connect facts from different documents to the same item of work. | Implemented | `WorkItem`, `extraction/work_items.py`. Deterministic and layered: exact item identifier, then a normalised form (case, separators, per-segment leading zeros). Every link records which layer matched it, so a weaker match is visibly weaker — and that field is the seam for semantic matching later. No embeddings, no model |
| FR-112 | The system shall reconcile contracted, measured and claimed quantities into an evidence-backed finding. | Implemented | `verification/reconciliation.py`, three rules over one work item, `analyse --all-projects`, `GET /v1/projects/{id}/work-items`. Verified end to end on a synthetic project: item 4.7.2 contracted 500 m³, measured 470 m³, claimed 520 m³ → variance +50 m³ → unsupported ₹400,000 → REVIEW, every value citing a named cell in a named file |
| FR-113 | The system shall distinguish a discrepancy requiring review from a rule failure. | Implemented | `Outcome.REVIEW`. A claim exceeding measured work may be an error, a timing difference, or an unrecorded variation. The rule establishes the discrepancy but not its cause, and calling that a failure would assert more than the evidence supports |
| FR-114 | The system shall refuse to compare quantities in different units. | Implemented | `_comparable_pair` in `calculation/engine.py`. There is no conversion table and there should not be one until a real document needs it: a silent tonne-to-cubic-metre conversion is a fabricated density. Covered by test, because a refusal produces nothing and nothing is invisible in a report |
| FR-115 | The system shall record whether a document is the current version of what it describes. | Implemented | `DocumentVersionState` (`active`/`superseded`/`retired`/`unknown`) on `documents`, with `version_state_reason`. Never inferred — not from a filename containing "Rev2", a revision number in the text, or upload order. Defaults to `active` because absent evidence of supersession a document *is* current |
| FR-116 | The system shall record supersession as an explicit, authored relationship. | Implemented | `RelationshipType.SUPERSEDES` via `extraction/supersede.py` and `aedifex-crawl supersede`, storing `operator:<who>`. Refuses a self-supersession or two documents sharing no project. Mutual supersession makes both documents `unknown` rather than picking one |
| FR-117 | The system shall select evidence deterministically, never by row order. | Implemented | `extraction/selection.py`. Replaced `{fact.fact_type: fact for fact in facts}`, which kept whichever fact the database returned last — correct only while every version agreed. Policy: exclude non-active documents, newest extractor version per document, one candidate wins, agreeing candidates win, disagreeing candidates resolve to nothing |
| FR-118 | The system shall refuse to reconcile a work item whose active documents disagree. | Implemented | `work_item_evidence_unambiguous`, returning `REVIEW` and naming every conflicting document and value. A separate rule because the others guard only the facts they read, and a conflict in `contracted_quantity` — which reaches them via a derived value — produced no finding at all on the first run |
| FR-119 | The system shall preserve superseded evidence and report what it excluded. | Implemented | Nothing is deleted: both raw objects stay in the immutable tier and both fact sets stay queryable. Verified by execution — item 4.7.2 shows 500 from the superseded Rev 01 and 550 from the active Rev 02, and the CLI lists excluded facts rather than hiding them |
| FR-120 | The system shall tie a derived fact to the exact facts it was computed from. | Implemented | `derived_facts.inputs_fingerprint`, a digest of role-to-fact-id pairs. Calculation version alone was insufficient: a value goes stale when its *inputs* change — a document leaving active selection, or a newer fact replacing an older one — and the version moves for neither |
| FR-121 | The system shall read a priced bill of quantities from a PDF, including credit rows and sub-items. | Implemented | `extraction/pdf_boq.py`. A real bill is a PDF, not a spreadsheet. Three defects here were money defects and all were found by running real data: a credit written in accounting parentheses (`(11,81,174.40)`) was invisible, overstating the bill by ₹11.8 lakh; items priced through sub-items `(a)`/`(b)` were refused; and the grand-total row was absorbed into the last item. Every row is still checked arithmetically before it is emitted, and one that does not close is reported rather than returned |
| FR-122 | The system shall verify that a bill of quantities adds up to the total it states for itself. | Implemented | `verification/bill_total.py`, `bill_items_reconcile_to_stated_total`. The first check a quantity surveyor makes, and it is a check on the evidence chain as much as on the document: a bill that does not add up is as likely to mean the extraction is untrustworthy as that the document is. REVIEW rather than FAIL for exactly that reason. Verified on the real NHAI bill — 37 rows reconciling to ₹8,46,49,969.01, difference ₹0.00 |
| FR-123 | The system shall sum a table's rows as a derived fact with one recorded input per row. | Implemented | `bill_items_total` in `calculation/engine.py`. A rule that added the facts up itself would reach the same figure and be able to prove nothing about it; the derived fact carries 37 `derived_fact_inputs`, so the total unfolds into the pages it came from. Its `expression` is the whole addition as text |
| FR-124 | The system shall not collapse a table's repeated facts to one fact per type. | Implemented | `FactSet` in `extraction/store.py`, returning every persisted fact alongside the document-scoped ones. | FR-125 | The system shall make every conclusive finding traceable to an immutable raw artifact. | Implemented | `scripts/audit_traceability.py`, `make audit-traceability`. | FR-126 | The system shall cite the evidence behind a pass, not only behind a discrepancy. | Implemented | `work_item_evidence_unambiguous` returned PASS with no citations at all — "every value used is stated by exactly one active document", naming none of them, with an `observed` of "0 conflicts" no reviewer could check. | FR-127 | The system shall treat every acquisition path as equivalent after acquisition. | Implemented | Origin affects provenance and nothing else: `document_retrievals` records a URL and HTTP status, `document_uploads` a path and an uploader, and extraction, calculation, verification, the knowledge registry and the API never read either. `StorableFile` is a Protocol so an upload needs no fabricated HTTP fields. `_document_origins` unions both for the one query that must filter by source — which previously joined retrievals alone and saw 0 of 5 uploaded documents |

A provision carries what a fact never does — authority, jurisdiction, effective date, applicability band — and lacks what a fact always has, a subject. Forced by the NHAI Works Manual, which made the tender-tuned reader record `estimated_cost = ₹20 crore` as a fact about a 297-page procedure manual and then cite it as evidence |
| FR-129 | The system shall require positive evidence of self-metadata before emitting document-scoped facts from a reference document. | Implemented | `_REFERENCE_DOCUMENT_TYPES` and `_self_metadata_evidence` in `extraction/runner.py`. The test is one positive signal — does the document name the tender it concerns — rather than a list of policy-language patterns, which would be endless and still miss the next phrasing. Suppressions are reported, not silent |
| FR-130 | The system shall extract a threshold stated in words and conditional on a band. | Implemented | `extraction/policy.py`. NHAI clause 4.14.1 writes "two percent" and "one and one-half percent", each conditioned on a cost band with a cap. A digits-only reader reported the clause as absent, which is how the project came to believe NHAI had no bid-security policy. An unrecognised wording is refused, never guessed |
| FR-131 | The system shall apply a reference provision to a project only through explicit, evidence-backed applicability. | Implemented | `extraction/applicability.py`, per ADR 0014. Two recorded facts must match: the authority read from the reference document's own text, and the project's stated cost falling in the provision's band. No global flag, no null-project wildcard. Project isolation is not weakened |
| FR-132 | The system shall report ambiguous applicability rather than resolving it. | Implemented | Clause 4.14.1's bands both contain exactly ₹20 crore as written. A cost landing there matches two provisions and resolves to INCONCLUSIVE citing both, because picking the lower rate favours the bidder and the higher favours the authority |
| FR-133 | The system shall cite a policy provision as a third, distinct kind of evidence. | Implemented | `finding_evidence.provision_id` and `derived_fact_inputs.provision_id`, each under a check constraint permitting exactly one kind. A threshold is not a measurement and not a calculation; the CLI labels it `policy` so a reader can tell a cited rule from a cited figure. `scripts/audit_traceability.py` traces provisions to their document and digest |
| FR-134 | The system shall verify a tender's bid security against the authority's own published rate schedule. | Implemented | `bid_security_matches_reference_policy`. Verified end to end on real data: estimated cost ₹8,46,49,969 selects clause 4.14.1(a) at 2%, requiring ₹16,92,999.38 against a stated ₹16.93 Lacs — PASS within a ₹1 tolerance, chosen because the next-coarsest plausible rounding would be ₹620 away |
| FR-082 | The system shall perform all arithmetic and equality checks in deterministic code, never via a language model. | Implemented | `verification/rules.py`. `Decimal` throughout, no model consulted anywhere in the path. Money in binary floating point is a defect waiting for a total, and these figures reach a division and a percentage comparison |
| FR-083 | The system shall reference exact source evidence for every finding. | Implemented | `finding_evidence` joins each finding to the facts it read, by role; every fact carries page, span and a verbatim snippet. A join table rather than a JSON id list, so the database refuses a finding citing a fact that no longer exists |
| FR-084 | The system shall report missing mandatory evidence as a finding. | Implemented | `Outcome.INCONCLUSIVE`, with `expected = NOT SOURCED` and the reason named in the summary. A document whose bid security could not be extracted has not passed and has not failed, and saying so is the difference between verification and manufacturing verdicts |
